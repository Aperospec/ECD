# Reference Policy

## Purpose

This policy governs factual, editorial, visual, structural, and production references across ECD.

A reference has a defined role. It is not an undifferentiated template.

## Reference roles

Assign one or more explicit roles:

- source / evidence;
- authorized content asset;
- concept reference;
- world-structure reference;
- mood / atmosphere reference;
- style / material reference;
- color / light reference;
- composition reference;
- typography or image–type reference;
- interaction / workflow reference;
- quality benchmark;
- negative reference.

Only assigned roles are active.

## Reference record

```markdown
Reference:
Source / owner:
Assigned role or roles:
Why it was supplied:
Source statement from ECD:
Authorized direct-use content:
Transferable principles:
Attributes open to professional interpretation:
Elements outside the mandate:
Rights / license / attribution:
Version / date / region limits:
Downstream consequence:
Open question:
```

## Four-pass reading

For material visual references, use:

### 1. Description

Record observable content without interpretation.

### 2. Formal analysis

Analyze organization through composition, scale, line, shape, value, color, light, depth, rhythm, salience, framing, and viewer relationship.

### 3. Interpretation

Explain the perception or meaning produced by those formal relationships.

### 4. Controlled transfer

Specify which relationships support the accepted project, which source-specific elements may be used directly, what remains open, and what lies outside the reference mandate.

Keep observation, interpretation, and ECD authority separate.

## Governing relationship

```text
Accepted project meaning
+ Accepted Script or professional task
+ Explicit reference role
→ Original project-specific solution
```

Reference analysis supports the accepted project. It does not replace premise development, editorial architecture, or visual concept development.

## Direct-use assets

For direct use or transformation, record:

- ownership and provenance;
- permitted use;
- permitted transformation;
- attribution;
- publication and commercial limits;
- protected identity or evidence requirements.

Evidence assets retain the context needed for accurate interpretation.

## Creative transfer

Creative transfer focuses on principles and relationships relevant to the assigned role. Any source-specific subject, scene, symbol, composition, identity, or branded expression requires separate authorization and project justification.

Similarity review asks:

- does the new work solve the accepted project through its own system;
- are transferred principles distinguishable from copied expression;
- does the solution still work when the reference is removed;
- are source-specific elements present only when authorized and necessary.

## Stage responsibility

### Creative Producer

Records intended use, authority, rights, and stage activation.

### Research function

Verifies source, evidence, provenance, license, attribution, version, and practical conditions when required.

### Editorial Director

Uses references only for activated editorial purposes. It derives content from the Greenlit Treatment and Activated Editorial inputs.

### Art Director

Performs detailed visual reading after Visual activation and applies assigned reference roles to original concept development.

### Production Artist

Uses only accepted assets, transformations, and reference-derived instructions recorded in the Art Direction Package.

## QA

Before handoff confirm:

- every material reference has an assigned role;
- original ECD intent is preserved;
- observation, interpretation, and authority are distinguishable;
- direct-use rights and attribution are known;
- only activated roles influence the current stage;
- source-specific expression is not carried forward without authorization;
- evidence remains accurate and inspectable;
- downstream instructions state both transferable principles and boundaries.
