# Content Architecture Skill

## Purpose

Content Architecture adapts an approved communication progression into a publishable format and sequence.

It does not invent the core story or argument for the first time, write final prose, decide final visual style, or split source material mechanically into pages.

## Required authority

Before formal page architecture begins, one of the following must be true:

- a Core Communication Script has separate ECD alignment;
- the High-Leverage Decision Record validly combines Core Script scope with Creative Script Alignment because dependency risk is low;
- an identifiable authority-complete Core Communication Script supplied by the ECD is being reused;
- the current bounded task legitimately has no Core Script requirement.

When Separate Core Script Alignment is required but unresolved, stop and return to Editorial Director. Do not create page architecture provisionally.

## Inputs

- Greenlit Treatment and Development decisions;
- Core Communication Script and gate mode;
- Core Script Alignment evidence when required;
- audience, platform, deliverables, and viewing conditions;
- source posture, Evidence Obligation, claim, disclosure, and rights boundaries;
- active Editorial inputs and references;
- user feedback;
- Editorial Director assignment.

## Method

### 1. Reconstruct the approved progression

Identify:

- communication form;
- opening;
- essential beats;
- decisive shift, discovery, comparison, explanation, or synthesis;
- ending / payoff;
- order constraints;
- adaptable examples and expressions;
- audience state before and after each major beat.

Do not substitute a nearby progression because it appears easier to paginate.

### 2. Choose the minimum sufficient format

Decide whether the project needs:

- one screen;
- cover plus one body page;
- short carousel;
- extended sequence;
- evidence-led post;
- mixed format.

Do not add pages to create a feeling of completeness.

Page count is an adaptation decision, not part of the Core Script unless the ECD explicitly made it authoritative.

### 3. Map Core Script beats to pages or states

For every approved beat, record how it is preserved:

```markdown
Core Script beat ID:
Essential meaning or event:
Mapped page(s) / state(s):
Adaptation action:
- direct
- compressed
- expanded
- combined
- split
Tolerance used:
Why the mapping preserves the approved progression:
```

Every essential beat must be represented. A beat may be omitted only through authorized Core Script revision.

### 4. Build the sequence map

For every page or state define:

```markdown
Page / state:
Core Script beat(s):
Editorial job:
Audience state before:
Internal Semantic Proposition:
Audience state after:
Required source / evidence:
Relationship to previous and next page:
Why this page is necessary:
```

Each page has one primary editorial job.

### 5. Test sequence integrity

- Remove each page: what is lost?
- Merge adjacent pages: does meaning improve or collapse?
- Are two pages making the same point?
- Is the payoff earned?
- Does the cover promise the actual sequence?
- Does the sequence preserve the aligned Core Script?
- Has an essential beat been weakened, relocated beyond recognition, or replaced?
- Does the sequence rely on information the audience never received?

### 6. Define Frame Script assignments

Translate each Internal Semantic Proposition and mapped Core Script beat into a clear Frame Script task without deciding final composition, palette, typeface, or image style.

## Self-check

- Was the actual Core Communication Script authority sufficient before page work?
- Is the format the minimum sufficient one?
- Does every page change understanding?
- Can every page be traced to an approved beat or legitimate adaptation function?
- Are essential beats and payoff preserved?
- Has the architecture avoided silently rewriting the Core Script?
- Are evidence and disclosures placed only where they matter?
- Have exact copy and visual decisions remained appropriately open?

## Failure routing

- Treatment lacks a coherent proposition → Development through Editorial Director;
- Core Script is weak, incomplete, rejected, or materially changed → Core Communication Script;
- required Core Script Alignment is missing → Editorial Director / Producer authority correction;
- source or evidence cannot support the approved progression → Development Research / Claims Rights;
- page cannot become visible or experiential → Frame Script;
- visual format constraints invalidate the adaptation → return through Producer for bounded Visual consultation.
