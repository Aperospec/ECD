# Minimum Professional Question Evals — V3.1

## Purpose

Verify that V3 is neither a department diagram nor a ceremonial waterfall.

Every professional question that materially affects the deliverable must be resolved with inspectable evidence and Department review. A registered Skill is used only when its professional question is active and not already resolved by a valid authoritative artifact.

The test therefore rejects both:

- missing professional work hidden behind role labels; and
- unnecessary simulation of every available Skill for every project.

## Universal routing evidence

Every project records:

1. Adaptive Route Record and Compact / Standard / Extended profile;
2. professional questions active;
3. professional questions already resolved by valid artifacts;
4. registered Skills selected;
5. Skills omitted, reused, or combined and why;
6. Evidence Obligation;
7. Stage-Scoped Input and Reference consequences;
8. Department Review based on actual artifacts.

Failure:

- every registered Skill is invoked because it exists;
- a Skill is omitted without showing that its professional question is absent or already resolved;
- one undifferentiated draft is relabelled as several professional passes without distinct method evidence;
- a role title substitutes for actual work.

## Development questions

Questions that may require resolution:

- Is the opportunity real and relevant?
- Is the premise, angle, or governing logic specific and coherent?
- What Evidence Obligation and public claim ceiling apply?
- What source, rights, attribution, or reference boundaries apply?

Possible evidence:

- Creative Strategy Return when opportunity or angle is open;
- Concept Development Return when governing logic or Treatment synthesis is open;
- Research Verification Return at the depth required by the Evidence Obligation;
- Claims Rights Return when third-party use, claims, reality position, or rights matter;
- validated existing Development artifact when it already resolves a question;
- Development Review Record;
- Department Cleared Treatment Package.

Failure:

- Treatment appears with no evidence for an active Development question;
- speculative work is burdened with irrelevant product validation;
- commercial reliability is claimed from one source example;
- downstream copy or design is embedded in Development.

## Editorial questions

Questions that may require resolution:

- What is the minimum sufficient format and sequence?
- What does every visual page or beat visibly contain?
- What exact page and publication language is required?
- What speaker, reality, claim, evidence, and disclosure position is correct?
- What native-language or bilingual craft is required?
- Is the final exact text clean?

Possible evidence:

- Content Architecture Return when structure is open;
- Frame Script Return for each unresolved visual page or beat;
- Copywriting Return when new language is required;
- Copy Editing Return when a completed draft requires independent challenge;
- Chinese or English Copy Craft Return for material audience-facing language;
- Bilingual Transcreation Return when multiple languages are required;
- Proofreading Return for final exact text;
- validated existing Editorial artifact when authority-complete;
- Editorial Review Record;
- Department Cleared Creative Script Package.

Failure:

- a typo-only task simulates the full Editorial department;
- an end-to-end new Script omits active architecture, Frame Script, language, or exactness questions;
- false or misleading first-person experience survives review;
- bilingual versions preserve literal words but not function or certainty;
- Visual decisions appear before Script Alignment.

## Visual questions

Questions that may require resolution:

- Is the governing visual thesis resolved?
- Does the whole sequence require low-cost staging?
- How do exact copy, imagery, typography, evidence, grid, and space form one system?
- Does imagery require dedicated direction?
- Has a separate critique pass inspected actual artifacts?

Possible evidence:

- Visual Concept Return when the visual thesis is unresolved;
- Storyboard / Sequence Return for multi-page or multi-state work when staging is unresolved;
- Editorial Design Return and METHOD evidence for text-bearing design;
- Typography Return when type is consequential;
- Image Direction Return when imagery is required;
- separate Design Critique Return on actual artifacts;
- validated existing Visual artifacts when authority-complete;
- Art Director Review Record;
- full required state / sequence coverage and representative fidelity proof;
- Department Cleared Visual Package.

Failure:

- a single-image project is forced through artificial multi-page work;
- one polished image stands in for the design system;
- exact copy is absent from representative proof;
- Critique is only a score or self-praise;
- all pages repeat one template;
- Art Director clears based on descriptions rather than artifacts.

## Production questions

Questions that may require resolution:

- Must final imagery be generated, transformed, extended, or repaired?
- Can the approved design be assembled faithfully?
- Does exact text fit and render correctly?
- Do actual exports, platform conditions, and variants pass?

Possible evidence:

- Image Production Return only when final imagery requires it;
- Finished Art Return when page assembly or final visual implementation is required;
- Production Typesetting Return for text-bearing final layouts;
- Technical QA Return based on opened exports;
- validated existing Production artifact for a narrow correction;
- Production Director Review Record;
- Editorial and Visual final sign-offs;
- Department Cleared Final Production Package;
- Producer Final Review.

Failure:

- a non-text image correction is forced through unnecessary typesetting;
- generated text is accepted as exact final copy;
- exported files are not opened and inspected;
- copy or design is silently changed for fit;
- Final Acceptance is requested without direct previews and sign-offs.

## Compact combination test

A Compact project may combine compatible execution seats or adjacent records when:

- each active professional question is still visible;
- method evidence remains distinguishable;
- the combined pass does not claim fictional independence;
- Department review remains a separate approval responsibility;
- ECD-facing output remains concise;
- required authority and stage boundaries remain intact.

Failure:

- `small project` is used to erase an active question;
- `professional rigor` is used to force every Skill and worksheet.

## Registration audit

For every `Implemented` entry in `core/CAPABILITY_REGISTRY.md` verify:

- file exists;
- frontmatter contains unique `name`;
- frontmatter contains usable `description`;
- Skill appears in installation feedback or runtime discovery;
- Director references the exact registered name;
- a sample task can produce the defined Specialist Return.

Registration audit proves availability, not universal mandatory use.

V3 is ready for project testing only when registration, adaptive routing, evidence obligation, stage-scoped input, reference, and native-language tests pass.
