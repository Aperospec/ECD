# Visual Metaphor Mapping

## Purpose

Visual Metaphor Mapping translates a conceptual relationship into a visual system before scene design or production.

A useful metaphor transfers structure, behavior, and relation. It does not rely on decorative resemblance alone.

## Inputs

- Greenlit Treatment;
- Accepted Creative Script;
- Visual Problem Statement;
- Activated Visual inputs;
- relevant reference readings;
- target surface and sequence requirements.

## Mapping model

### Target domain

State the project idea, relationship, or process that must become perceptible.

### Source domain

State the familiar system used to help the audience understand the target.

### Relational invariants

Identify the transferable relationships, such as:

- connection and separation;
- sequence and return;
- hierarchy and scale;
- accumulation and erosion;
- visibility and concealment;
- branching and convergence;
- transformation and continuity;
- boundary and passage;
- rhythm and interruption.

### Formal consequences

Translate each accepted relation into possible spatial, compositional, temporal, material, typographic, or interaction behavior.

### Literal-transfer limit

Identify source-domain details that are unnecessary to the relationship and require separate project justification before use.

### Proof requirement

Define the lowest-cost visual study that can show whether the metaphor is understandable and productive.

## Evaluation

A metaphor is viable when:

- it clarifies rather than replaces the project;
- several meaningful relations can be developed from it;
- it supports the full sequence rather than one isolated image;
- the source domain does not dominate the target meaning;
- it permits original formal solutions;
- its limits are explicit;
- representative proof can test it.

## Stage boundary

The map defines a generative relationship. It does not fix final objects, composition, palette, camera, or rendering style. Those decisions emerge through concept routes and formal studies.
