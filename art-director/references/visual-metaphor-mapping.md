# Visual Metaphor Mapping

## Purpose

Visual Metaphor Mapping turns an abstract creative proposition into a visual system by transferring **relationships and behavior**, not merely the visible objects of a source domain.

Use this protocol when the project contains statements such as:

- a life archive is a life amusement world;
- a figurine cabinet moves into the computer;
- a conversation becomes a museum;
- knowledge becomes a city, map, garden, machine, or stage.

A metaphor is not ready for production because it sounds evocative. It must be mapped, tested, and bounded.

## Core Distinction

### Target domain

The project meaning that needs to become perceptible.

### Source domain

The familiar system whose structures may help make that meaning visible.

### Relational invariant

The relationship or behavior worth transferring.

### Surface object

A literal object from the source domain. It may or may not belong in the final work.

Weak metaphor work copies surface objects. Strong metaphor work transfers useful relations and then designs a new visual world.

## Mapping Tests

### Relation-before-object test

Can the metaphor still work if the source domain's most obvious objects are removed?

If “life amusement world” stops working without roller coasters and cable cars, the direction may be only thematic decoration.

### Generative-capacity test

Can the metaphor generate several distinct pages or regions while preserving one world logic?

A useful metaphor should support variation, not force every page into the same visual pun.

### Target-fidelity test

Does the source domain clarify the Greenlit project, or has the project become an illustration of the source domain?

### Audience-entry test

Will the audience understand the intended relationship without a paragraph of explanation?

### Literalization-risk test

What would make the work look like a real commercial park, tourism poster, game map, control center, or product UI rather than the intended concept?

### Mixed-metaphor test

Are archive, museum, amusement park, diary, database, map, and theater being used together without hierarchy?

Choose a governing metaphor and define supporting metaphors narrowly.

## Example — Life Archive as Life Amusement World

```markdown
Target domain:
A person's remembered life: fragmented, interconnected, revisitable, incomplete, and still growing.

Source domain:
An explorable amusement world containing multiple regions, routes, heights, pauses, returns, and simultaneous activities.

Relational invariants:
- memories exist as distinct but connected regions;
- a life is navigated rather than displayed from outside;
- paths branch, loop, rise, descend, and return;
- different intensities and periods coexist;
- the whole world remains unfinished because life continues.
```

Possible mapping:

| Target concept | Source structure | Visual translation | Avoid |
|---|---|---|---|
| memory episodes | themed regions | distinct lived zones within one world | one memory = one ride |
| non-linear life path | branching / looping routes | paths reconnect distant periods | filling every frame with tracks |
| growth and difficulty | ascent, descent, threshold | changes in altitude and access | “growth = tower” illustration |
| revisiting | return path / lookout | present route reveals an earlier zone | generic person looking at sunset |
| loss and absence | closed or quiet region | restrained interruption, missing connection, darkened space | haunted-house melodrama |
| life continuing | unfinished territory | route extends into forming space | repetitive construction cranes |
| AI relation | indexing / linking logic | subtle connection mechanism between disclosed memories | AI as park manager or surveillance center |

The project should retain:

- one coherent world;
- navigability;
- layered routes;
- macro scale with micro life;
- discovery and return;
- active but not purely commercial energy.

The project should not automatically retain:

- roller coasters;
- cable cars;
- branded attraction signage;
- shops and souvenir logic;
- the reference mountain silhouette;
- a tourism-ad composition.

## Metaphor and Script Relationship

The map may propose ways to visualize accepted Script meaning. It may not rewrite the Script to fit a convenient visual device.

When the metaphor cannot serve a page without changing its editorial job, return to Art Director framing or Editorial Director as appropriate.

## ECD Alignment

Present the metaphor in plain language:

- what the project becomes visually;
- which relationship is being borrowed;
- which literal objects are not essential;
- the most likely wrong interpretation;
- the low-cost proof that will test it.

Do not ask the ECD to approve a technical mapping table without a synthesized explanation.

## Gate

A strong new metaphor or a material reinterpretation of the visual world requires a Visual Direction Alignment before Storyboard or anchor production.

Do not use a metaphor as an image-generation prompt until its governing relations and prohibited literalization have been recorded.
